## 0. 전제 — 현재 상태와 목표

### 현재 4역할의 "첫 화면"이 가진 한계
- **/admin** — 가입 승인 1카드만. 좌측 네비에 다른 기능 5개가 흩어져 있어 관리자 작업의 전체 흐름이 안 보임.
- **/teacher** — 상단에 3개 텍스트 링크(교과 학습/콘텐츠 블록/학급 기록) + 디버그성 "Supabase 연결 상태" + 세션 만들기 폼 + 세션 20개 목록. 정보 위계가 무너져 있고 진도표·세특·통계 기능 자체가 없음.
- **/student/home** — "내 학생 정보" 카드 + "내 활동 기록" 리스트. 활동 결과 표시 스키마가 옛 ProbabilitySimulator 한정(modeLabel/n/p/observedMean…)이라 새로 이식한 60+ 활동에는 결과 칸이 비어 보임.
- **일반인 대시보드 = 없음**. 로그인 후 /learn로만 진입.

### 목표
- "AI 교과서·교육용 코스웨어" 스타일의 카드 그리드 대시보드.
- 역할별 첫 화면이 그 역할의 핵심 작업을 한눈에 보여주고, 상세는 하위 페이지로 라우팅.
- 상단 가로 링크 나열을 걷어내고, 본문 안에 아이콘+제목+한 줄 설명+미니 KPI를 가진 "기능 카드" + "최근 활동" 게시판형 영역으로 재배치.
- PC primary + 모바일 지원(반응형, 모바일은 카드 세로 스택 + 하단 탭바 고려).
- 다크 slate-950 + cyan/amber 액센트 유지 + 역할별 보조 색(아래 §6).

### ★ 전역 원칙 — 관리자 = 슈퍼유저
- 관리자는 **다른 역할(교사·학생·일반인)이 할 수 있는 모든 화면·기능·콘텐츠에 접근할 수 있다**.
- 구체적으로:
  - 모든 교과의 수업(`/learn`)을 전부 본다 — 본인이 권한받은 교과뿐이 아니라 등록된 모든 교과·단원·블록.
  - 교사 화면(`/teacher/*`)을 본인의 담당 학급 제한 없이 전체 학급·전체 교과 범위로 본다(진도표·세션·학급 기록·콘텐츠 편집·세특·학생 상세).
  - 학생 화면(`/student/*`)·일반인 화면(`/general/*`)을 "읽기 모드"로 진입해 학생이 무엇을 보는지 확인할 수 있다 (단, 학생/일반인의 개인 성찰·기록을 본인 행세로 작성하지 않는다 — 검수·열람 한정).
- 헤더 사용자 메뉴에 **"역할 뷰 전환"** 셀렉트 (`관리자 / 교사 보기 / 학생 보기 / 일반 보기`) 추가 → 클릭 시 해당 역할의 대시보드 라우트로 이동. 관리자임을 알리는 작은 뱃지는 계속 표시.
- 기술적으로:
  - 기존 게이트 함수(`requireTeacher`)는 이미 `role in (teacher, admin)`을 통과시키고 있음 — 이 패턴을 학생/일반인 게이트에도 동일 적용(`requireStudent`/`requireGeneral`이 admin 통과).
  - RLS는 관리자 권한 SECURITY DEFINER 헬퍼(`is_admin()`)가 이미 있고 정책에서 `is_admin() OR (역할별 조건)` 패턴을 쓰고 있어 추가 작업 없이 충족.
  - 진도표(`progress_tracker`) 등 신규 테이블의 RLS는 처음부터 `admin ALL + (역할 본인 조건)`으로 기술.

## 1. 사용자가 제시한 기능 (원본)

### [관리자]
1. **회원관리** — 가입승인, 권한부여, 비밀번호 수정
2. **세팅** — 교과 및 학급, 그룹관리
3. **건의사항** — 오류제보 / 추가 만들어주었으면 하는 활동
4. **통계**
   - 회원별 접속이력
   - 회원 종류(교사·학생·일반인)별 접속이력
   - 일간/주간/월간/연간 접속자 수 (회원 중복 제외 누적 카운트)
   - 각 교과별·활동별 학생들의 수행 횟수 (어떤 활동이 인기 있는지)

### [교사]
1. **진도표** (방식은 기존 웹앱 참고) — 교사별 각자 저장
2. 해당 주의 전주까지 포함해서 2주치의 진도표를 제시
3. **담당 교과의 수업자료** — 소단원별로 각자의 스타일로 편집하는 모드
4. **담당 학급 학생 접속 이력 / 빈도**
5. **담당 학급 학생의 성찰 기록 열람**
6. **AI를 이용한 세특 기록 작성**
7. **회원 정보 관리** (비밀번호 수정 등)

### [학생]
1. 자신이 속한 학급의 수업 자료 열람
2. 자신의 접속 이력 / 빈도
3. 자신이 수행한 활동의 내역 — 활동 적은 학생에게 독려, 많은 학생에게 칭찬
4. **자신이 입력한 성찰 기록 열람**
   - 생기부 작성 시 어떤 성찰을 바탕으로 쓸지 **체크 기능**
   - 체크된 내용 중 우선순위 설정
   - 교사가 열람 시 우선순위 표시 + AI 세특 작성 시 우선순위를 입력으로 반영
5. **관리자에게 건의사항 보내기** (오류제보·활동 건의)
6. **회원 정보 관리**

### [일반인]
1. 자신에게 허가된 수업내용 열람 (수업 편집은 불가)
2. 회원 정보 관리

## 2. 내 보완 제안 (사용자의 안에 덧붙이거나 다듬는 것)

### 2-A. 관리자 — 추가/조정 제안
- **첫 화면 상단에 KPI 카드 4개**: 가입대기 / 진행 중 세션 / 오늘 접속자 / 누적 활동 수행 — 한눈 파악.
- **회원관리 페이지 통합 제안**: 현재 흩어진 `/admin`(승인 대기) + `/admin/teachers` + `/admin/roster` + `/admin/subjects`(교과 접근) + `/admin/settings`(과목·학급)를 **회원관리 / 마스터 세팅 / 권한** 3개 묶음으로 정리.
  - `/admin/members` (회원관리): 가입 승인, 회원 검색·상태 변경, 비밀번호 재설정, 명렬표 가져오기/내보내기 통합.
  - `/admin/settings` (마스터): 과목, 학급, 현재 학년도.
  - `/admin/access` (권한): 교사 담당 학급, 학생 학급 단위 교과 접근, 일반인 개인 교과 접근.
- **건의사항** — 상태(접수/검토중/처리완료/반려), 카테고리(오류 제보/활동 건의/기타), 답변/알림 기능.
- **통계** 외 시스템 건강성 지표:
  - 유지율(이번 주 활동한 학생 비율 / 누적 등록 학생 대비)
  - 세션 활용도(만든 세션 중 실제 응답 받은 비율)
  - 미연결 활동 슬러그 / 콘텐츠 부재 단원 자동 표시
- **공지 발송** — 교사/학생 첫 로그인 화면에 띄울 공지(예: "신학기 명렬표 등록 부탁드립니다") 작성·예약.
- (장기) **데이터 내보내기** — 학기말 활동·성찰·세특 일괄 CSV/PDF.

### 2-B. 교사 — 추가/조정 제안
- **"오늘의 수업" 우선 카드** — 진도표 오늘 행을 인라인으로 노출 + "이 진도로 세션 만들기" 1클릭 버튼(활동 자동 제안).
- **진도표 ↔ 세션 연동** — 진도표 칸에서 바로 세션 생성, 세션 종료 시 진도표에 자동 기록.
- **자주 쓰는 활동 즐겨찾기** — 학기마다 반복하는 활동 빠른 진입.
- **학생 관찰 메모(교사 비공개)** — 학생별 짧은 메모 누적 → 세특 작성의 중요 입력.
- **세특 작성 워크플로우**: AI 초안 → 교사 편집 → 저장(버전 기록) → 학기말 NEIS 복붙용 텍스트 일괄 출력.
- **알림 영역** — 새 응답 도착, 마감 임박, 관리자 공지.
- 학생 접속 이력 = 마지막 접속일 + **주간 활동 빈도 히트맵**(시각화).

### 2-C. 학생 — 추가/조정 제안
- **"이번 주 / 오늘 수업" 카드** — 교사의 진도표·세션을 학생용으로 자동 노출(복습 동선).
- **활동 빈도 게이미피케이션** — 누적 활동 수, 주간 +N, 단원 완수 배지, 연속 출석 스트릭. (사용자 의도가 "독려/칭찬"이라 시각적 보상 요소가 효과적.)
- **이어보기 카드** — 마지막 본 단원/블록 자동 추천.
- **성찰 우선순위 UI**: 별표(★) 토글 + 1·2·3 우선순위 + 활동·단원 태그 + 코멘트.
- **본인 성장 그래프** — 성찰 기록 누적 추이, 단원 진도 도넛.
- **알림** — 교사 메시지, 새 수업 자료 도착, 세특 작성 기간 안내.
- **자신의 접속/활동 이력** 표시는 "혼나는 화면"이 되지 않도록 — 부족할 때는 단어 톤(예: "이번 주 활동을 더 해볼까?")으로 부드럽게.

### 2-D. 일반인 — 추가/조정 제안
- **"내 학습 진도" 카드** — 마지막 본 단원, 북마크.
- 본인 활동/성찰 기록 (학생과 동일 패턴 단순화).
- 회원 정보 관리 — 비밀번호·연락처.
- "수업 편집 불가"는 UI에서 편집 진입점 자체를 숨기는 형태(권한 없음 안내가 아니라).

### 2-E. 공통 UI/UX
- **상단 단일 헤더(고정)** — 로고 + 페이지 타이틀 + 사용자 메뉴(이름/역할 뱃지/로그아웃) + (장기) 알림 종 + 검색.
- **본문 = 그리드 카드 대시보드**:
  - 상단: KPI/상태 카드 가로 4개 (모바일=세로 2×2)
  - 중단: 기능 카드 그리드 — 아이콘 + 제목 + 한 줄 설명 + 미니 KPI/배지 → 클릭 시 상세 페이지로
  - 하단: "최근 활동 / 이어보기 / 게시판" 등 동적 영역
- **데스크톱**: 좌측 사이드바(역할별 메뉴) + 메인 그리드.
- **모바일**: 카드 세로 스택 + 하단 탭바(홈/학습/기록/내정보) — AI 코스웨어 패턴.
- **빈 상태(empty state)**는 친근한 일러스트/문구.
- **카드 hover**: 살짝 들리는 transition, 둥근 모서리(rounded-2xl), 그라데이션 보더.

### 2-F. 디자인 토큰
- 베이스 — `bg-slate-950`, `text-slate-100`, `border-white/10`.
- 주 액센트 — `cyan-300` (기존 유지).
- 보조 액센트 — `amber-300` (강조/관리자 전용 표시는 amber 토널).
- **역할별 컬러 액센트(헤더 뱃지·미니 KPI 톤)**
  - 관리자 = `violet-300`
  - 교사 = `cyan-300` (기존)
  - 학생 = `emerald-300`
  - 일반 = `amber-300`
- KPI 카드 큰 숫자: `text-cyan-200 font-bold text-3xl`, 라벨 `text-xs text-slate-400`.
- 카드 패딩: `p-5 sm:p-6`, 그리드 gap-4 sm:gap-5.

## 3. 새 페이지 구조 (라우팅)

### `/admin`
- `/admin` → **대시보드 홈** (KPI 4 + 기능 카드 그리드 + 최근 가입/건의)
- `/admin/members` (회원관리: 승인 + 학생/교사/일반인 검색·관리 + 비밀번호 재설정 + 명렬표 통합)
- `/admin/settings` (과목·학급·학년도)
- `/admin/access` (교사 권한·학급 교과 접근·일반인 교과 접근 통합)
- `/admin/feedback` (건의사항)
- `/admin/stats` (통계)
- `/admin/notices` (장기) 공지 발송

### `/teacher`
- `/teacher` → **대시보드 홈** (오늘의 수업 + 기능 카드 + 최근 응답·알림)
- `/teacher/progress` 진도표 (2주치 + 학기 전체)
- `/teacher/sessions` 세션 관리 (현 /teacher 의 세션 부분 분리)
- `/teacher/records` 학급 기록 (그대로)
- `/teacher/activities` 활동 콘텐츠 블록 (그대로, "공유 템플릿")
- `/teacher/sebteuk` 세특 작성 (학생 검색 → AI 초안 → 편집 → 저장)
- `/teacher/students/[id]` 학생 상세 (성찰+활동+교사 메모 — 세특 작성의 기반)
- `/teacher/profile` 회원 정보 관리

### `/student`
- `/student/home` → **대시보드 홈** (오늘의 수업 + 활동 카드 + 이어보기 + 격려/배지)
- `/student/records` 본인 활동 기록 (현 home의 리스트 분리·재설계 — 범용 결과 표시)
- `/student/reflections` 성찰 모음 + 생기부 후보 체크 + 우선순위
- `/student/feedback` 건의 보내기
- `/student/profile` 회원 정보 관리

### `/general`
- `/general` → **대시보드 홈** (내 접근 교과 카드 + 학습 진도 + 회원 정보 진입)
- `/general/profile` 회원 정보 관리
- (학습은 `/learn` 공용, 일반인은 편집 진입점 숨김)

### 공용
- `/learn` (그대로, 4역할 공용, 일반인은 편집 X)
- `/join`, `/student/session/[joinCode]` (그대로)
- `/teacher/sessions/[id]/...` (그대로)

### 관리자의 라우트 접근 (§0 슈퍼유저 원칙 구체화)
- `/admin/*` — 관리자 전용 (다른 역할 차단).
- `/teacher/*` — admin도 통과(현재도 그렇게 동작). 본인 담당 학급 제한 없이 전체 학급·교과 노출.
- `/student/*`, `/general/*` — admin은 "읽기 모드"로 진입 허용 (작성·제출은 비활성/안내). 헤더 "역할 뷰 전환"이 이쪽 라우트로 이동시킨다.

## 5. 우선순위 — 1차(MVP) vs 2차 vs 장기

### 1차 (대시보드 셸 + 핵심 기능)
1. **공용 셸**: 상단 헤더(역할 뱃지) + 좌측 사이드바(데스크톱) + 하단 탭바(모바일) + 카드 그리드 컴포넌트 (`components/dashboard/`).
2. **관리자 홈** — KPI 카드 + 기능 카드 그리드 / 회원관리 통합 페이지 / 통계 KPI(기본 카운트만) / 건의사항 게시판 + 답변.
3. **교사 홈** — "오늘의 수업" 카드(진도표 인라인) + 기능 카드 그리드 + 최근 응답 / **진도표 페이지(주간 그리드, 본인용, 2주치 우선)** / 세션 만들기는 카드 → 별 페이지(`/teacher/sessions`).
4. **학생 홈** — 오늘의 수업/이어보기 + 활동 카드 + 격려 영역(누적 수) + 활동 기록 (재설계, 새 활동 결과 범용 표시) + 성찰 우선순위.
5. **일반인 홈** — 내 접근 교과 카드 + 학습 진도.
6. **건의사항** 테이블 + 학생/일반인 작성 페이지 + 관리자 답변.
7. **회원 정보 관리** — 비밀번호 변경, 이름·연락처 수정.

### 2차 (대시보드 위에서 자라나는 기능)
- 교사: **세특 AI 작성**(`/teacher/sebteuk`) + 학생 관찰 메모.
- 학생: 게이미피케이션(스트릭/배지/주간 그래프), 알림 종.
- 관리자: 통계 고도화(유지율, 활동 인기 그래프, CSV 다운, 시스템 건강성).
- 공지/알림 시스템 (`notifications`).
- 접속 이력(`login_logs`) — proxy.ts 통합.
- 진도표 ↔ 세션 자동 연동.

### 장기
- 즐겨찾기/북마크, 검색.
- 학기말 일괄 출력(세특·활동·성찰 PDF/CSV).
- 일러스트/모션 적용한 빈상태.
- 다국어(영재 학생 대상 검토).

- Step 3-1: `/teacher` 재작성, 세션 만들기는 `/teacher/sessions`로 이관. "오늘의 수업"은 자리만.

### Step 4. 학생 홈 재설계 + 활동 기록 범용화 (1 branch)
- `/student/home`을 카드 그리드로 재작성.

### Step 5. 일반인 홈 (1 branch)
- `/general/(home)` 신설.

### Step 6. 건의사항 (1 branch)
- `feedback` 테이블 + 마이그레이션 + `/student/feedback`, `/general/feedback` 작성 페이지 + `/admin/feedback` 처리.

### Step 7. 회원 정보 관리 (1 branch)
- `/teacher/profile`, `/student/profile`, `/general/profile` — 비밀번호 변경.

### Q5 신규 스펙 — AI세특 권한 관리 (관리자 승인제)
- AI세특은 Claude API 호출 = 실제 비용 발생 → **교사별로 관리자가 사용 승인**.
- 승인되지 않은 교사: **메뉴 자체를 노출하지 않음** ("권한 없음" 안내가 아니라 사이드바/카드 진입점 자체 숨김).
- 승인된 교사: 사이드바에 "🤖 세특 작성" 카드/메뉴 노출.
- 데이터 모델: `teachers` 테이블에 `ai_sebteuk_enabled boolean default false` 컬럼 추가.
  - 이유: profiles에 두면 admin/student/general에도 동일 컬럼이 생겨 의미가 흐려짐. teachers 1:1 행이 적절.
- UI:
  - `/admin/access` 페이지의 교사 카드에 "AI세특 사용 권한" 토글(또는 별도 탭 "AI세특 권한 관리").
  - 토글 변경은 즉시 반영(낙관적 UI + 실패 시 롤백).
  - 활성화 시 작은 안내: "이 교사가 AI세특 기능을 사용할 수 있게 되며 API 호출 비용은 시스템에 청구됩니다."
- 교사 사이드바/대시보드 렌더링: `requireTeacher` 결과에 `teachers.ai_sebteuk_enabled`를 함께 반환하도록 확장, **이 값이 true일 때만** 세특 카드/메뉴/라우트 노출. `/teacher/sebteuk` 페이지 자체도 ai_sebteuk_enabled=false면 redirect.
- RLS: `sebteuk_drafts` INSERT 정책에 `EXISTS (select 1 from teachers where profile_id=auth.uid() and ai_sebteuk_enabled = true) OR is_admin()` 조건 — 이중 잠금.
- 마이그레이션 분리: `20260530_ai_sebteuk_permission.sql` (teachers.ai_sebteuk_enabled) + `20260530_sebteuk_drafts.sql` (테이블 + RLS).

### Q6 반응형 정책 구체화
- **학생 화면**: 모바일 360px부터 자연스럽게, **태블릿(iPad 768~1024)이 일급 폼팩터**(우리 학교는 학생 아이패드 활용), PC도 무리 없게.
- **교사 화면**: **PC + 태블릿(iPad) + 전자칠판** 우선. 진도표·기록 표는 가로 스크롤 허용. 모바일에서는 핵심 기능(세션 만들기, 학생 응답 확인)만 보장.
- **관리자 화면**: PC 위주.
- Tailwind 분기 기준:
  - `sm` (640px) — 모바일 가로/소형 태블릿 세로
  - `md` (768px) — iPad 세로
  - `lg` (1024px) — iPad 가로 / 작은 PC, **표↔카드 전환선** (기존 정책 유지)
  - `xl` (1280px) — 일반 PC
  - `2xl` (1536px) — 전자칠판/와이드
- 카드 그리드: 모바일 1열 → md 2열 → lg 3~4열 → xl 4열.

→ 위 결정들이 §3 라우팅, §4 데이터 모델, §5 우선순위에 이미 반영되었거나 아래 §9에 추가됨.
