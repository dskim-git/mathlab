## 1. 메모 목적

기존 Streamlit 앱에서는 수업 화면을 다음 구조로 탐색했다.

```text
1. 과목 선택
2. 대단원 선택
3. 중단원 선택
4. 소단원 선택
5. 소단원 안의 여러 컴포넌트를 아래로 스크롤하며 사용
```

이 방식은 과목과 단원 체계를 반영하기에는 좋지만, 소단원 안에 컴포넌트가 많아질수록 화면 스크롤이 길어지는 문제가 있었다. 또한 Canva PPT나 PDF 자료를 보다가 중간에 미니활동으로 이동한 뒤 다시 돌아오면, 임베딩 자료가 처음 페이지로 돌아가서 수업 흐름이 끊기는 문제가 있었다.

이 문서는 새 MathLab에서 수업 화면 UI와 탐색 구조를 어떻게 개선할지 정리하기 위한 메모이다.

---

## 2. 기존 방식의 장점과 문제점

### 2.1 장점

```text
- 과목 → 대단원 → 중단원 → 소단원 구조가 교육과정 체계와 잘 맞는다.
- 교사가 원하는 단원을 찾기 쉽다.
- 하나의 소단원 안에 PPT, 영상, 미니활동, PDF 등을 모두 모아둘 수 있다.
```

### 2.2 문제점

```text
- 소단원 안의 컴포넌트가 많아지면 스크롤이 너무 길어진다.
- 수업 중 특정 컴포넌트로 빠르게 이동하기 어렵다.
- PPT 임베딩을 보다가 미니활동을 다녀오면 PPT가 처음 페이지로 돌아갈 수 있다.
- 영상, PDF, 외부 임베딩, 미니활동이 한 화면에 길게 나열되면 집중도가 떨어진다.
- 교사용 수업 진행 화면과 학생 활동 화면의 목적이 섞일 수 있다.
```

---

## 3. 새 UI의 핵심 원칙

새 MathLab의 수업 화면은 다음 원칙을 따른다.

```text
1. 교육과정 탐색 구조는 유지한다.
2. 하지만 소단원 안에서는 긴 스크롤 나열을 피한다.
3. 콘텐츠는 블록 단위로 관리한다.
4. 수업 중에는 현재 사용할 블록 하나에 집중할 수 있게 한다.
5. PPT, PDF, 영상, 미니활동을 빠르게 전환할 수 있게 한다.
6. 가능한 경우 각 블록의 상태를 유지한다.
7. 새 컴포넌트 유형은 나중에 쉽게 추가할 수 있어야 한다.
```

## 4. 권장 화면 구조

### 4.1 전체 구조

기본 탐색은 다음처럼 유지한다.

```text
과목
→ 대단원
→ 중단원
→ 소단원
→ 수업 흐름 화면
```

단, 소단원 내부는 긴 스크롤이 아니라 다음 구조를 권장한다.

```text
상단: 과목 / 단원 / 소단원 정보
좌측 또는 상단: 콘텐츠 블록 목차
중앙: 현재 선택한 콘텐츠 블록
하단 또는 우측: 수업 진행 보조 도구
```

---

## 5. 소단원 내부 UI 후보

### 5.1 탭형 구조

소단원 안의 각 컴포넌트를 탭으로 배치한다.

```text
[수업 PPT] [영상] [미니활동] [PDF] [외부자료] [성찰]
```

장점:

```text
- 긴 스크롤을 줄일 수 있다.
- 원하는 자료로 빠르게 이동할 수 있다.
- 교사가 수업 중 자료를 전환하기 쉽다.
```

단점:

```text
- 탭이 너무 많아지면 다시 복잡해진다.
- 수업 흐름의 순서가 약해질 수 있다.
```

적합한 경우:

```text
- 한 소단원에 3~6개 정도의 블록이 있는 경우
- PPT, 영상, 미니활동, PDF를 빠르게 오가야 하는 경우
```

---

### 5.2 단계형 수업 흐름 구조

콘텐츠 블록을 수업 순서에 따라 단계로 보여준다.

```text
1. 도입 PPT
2. 개념 영상
3. 미니활동 1
4. PDF 학습지
5. 미니활동 2
6. 성찰 제출
```

화면에는 현재 단계 하나를 크게 보여주고, 좌측 또는 상단에 단계 목록을 둔다.

장점:

```text
- 수업 흐름이 명확하다.
- 학생들이 지금 무엇을 해야 하는지 알기 쉽다.
- 교사가 단계별로 수업을 진행하기 좋다.
```

단점:

```text
- 자료를 자유롭게 오가는 탐색성은 탭형보다 약하다.
```

적합한 경우:

```text
- 수업 흐름이 정해져 있는 활동
- 교사가 전체 학생을 같은 순서로 안내하는 수업
- 학생이 순서대로 활동해야 하는 수업
```

---

### 5.3 목차 + 현재 블록 집중형 구조

좌측에 목차를 두고, 중앙에 선택된 블록만 표시한다.

```text
좌측 목차:
- 01 도입 PPT
- 02 개념 영상
- 03 확률 시뮬레이터
- 04 활동지 PDF
- 05 성찰 제출

중앙:
- 현재 선택된 콘텐츠 블록 표시
```

장점:

```text
- 긴 스크롤을 피할 수 있다.
- 자료 전환이 쉽다.
- 수업 순서와 자유 탐색을 모두 어느 정도 만족한다.
- 콘텐츠 블록이 많아져도 비교적 안정적이다.
```

단점:

```text
- 모바일 화면에서는 좌측 목차를 접이식으로 처리해야 한다.
```

현재 MathLab에 가장 적합한 후보이다.

## 6. 현재 추천안

현재 추천하는 UI는 다음이다.

```text
과목 / 대단원 / 중단원 / 소단원 선택 구조는 유지
+ 소단원 내부는 '목차 + 현재 블록 집중형'으로 구성
```

즉, 사용자는 단원까지는 기존처럼 선택한다.

```text
확률과 통계
→ 확률
→ 이항분포
→ 이항분포 시뮬레이션
```

그다음 수업 화면에서는 전체 자료를 길게 나열하지 않고, 블록 목차를 통해 이동한다.

```text
01 수업 안내 PPT
02 이항분포 개념 영상
03 확률 시뮬레이터
04 활동지 PDF
05 성찰 제출
```

중앙에는 현재 선택한 블록 하나만 크게 보여준다.

## 7. PPT 페이지 초기화 문제에 대한 대응

Canva PPT나 Google Drive PDF는 iframe 임베딩을 사용하면 내부 페이지 상태를 앱에서 완전히 제어하기 어렵다. 특히 컴포넌트를 unmount했다가 다시 mount하면 처음 페이지로 돌아갈 수 있다.

해결 방향 후보는 다음과 같다.

### 7.1 블록을 숨기기만 하고 제거하지 않기

탭이나 목차를 전환할 때 선택하지 않은 블록을 완전히 제거하지 않고 `display: none` 또는 유사 방식으로 숨긴다.

장점:

```text
- iframe 내부 상태가 유지될 가능성이 높다.
- PPT나 PDF가 처음 페이지로 돌아가는 문제가 줄어든다.
```

단점:

```text
- 여러 iframe이 동시에 로드되므로 초기 로딩이 무거워질 수 있다.
```

### 7.2 PPT/PDF는 별도 고정 패널로 유지

수업 PPT는 상단 또는 좌측에 고정하고, 미니활동만 아래 또는 오른쪽 패널에서 바꾸는 방식이다.

예시:

```text
왼쪽: Canva PPT 고정
오른쪽: 현재 활동 / 영상 / PDF / 성찰
```

장점:

```text
- PPT 페이지 상태를 유지하기 쉽다.
- 교사는 PPT를 넘기면서 오른쪽에서 미니활동을 진행할 수 있다.
```

단점:

```text
- 작은 화면에서는 답답할 수 있다.
- 학생용 화면과 교사용 화면을 다르게 설계해야 할 수 있다.
```

### 7.3 새 창 열기 보조 제공

임베딩 상태 유지가 어려운 자료는 앱 내부 임베딩과 함께 '새 창으로 열기' 버튼을 제공한다.

장점:

```text
- Canva, Google Drive, 외부 사이트의 iframe 제한을 우회할 수 있다.
- 교사가 발표 화면을 별도 창으로 유지할 수 있다.
```

단점:

```text
- 브라우저 창 관리가 필요하다.
```

## 8. 교사용 화면과 학생용 화면 분리 가능성

장기적으로는 같은 소단원이라도 교사용 수업 진행 화면과 학생용 활동 화면을 구분할 수 있다.

### 교사용 수업 진행 화면

```text
- PPT 중심
- 영상, PDF, 외부자료 빠른 전환
- 현재 학생 활동 링크 또는 입장 코드 표시
- 제출 현황 확인
```

### 학생용 활동 화면

```text
- 지금 해야 할 활동 중심
- 필요한 자료만 표시
- 제출 버튼과 성찰 입력 강조
- 불필요한 교사용 자료는 숨김
```

MVP에서는 한 화면 구조를 유지하되, 장기적으로는 교사용 프레젠테이션 모드와 학생용 참여 모드를 분리하는 것을 검토한다.

## 9. 콘텐츠 블록 확장성

현재 예상 블록 유형은 다음과 같다.

```text
canva_embed
interactive_activity
youtube_embed
external_embed
google_drive_file
```

하지만 나중에 다음 블록도 추가될 수 있다.

```text
text_instruction
image
quiz
poll
desmos_embed
geogebra_embed
file_download
student_upload
teacher_note
ai_feedback
record_draft
```

따라서 블록 렌더러는 새 block type을 추가하기 쉬운 구조로 만든다.

## 10. 추천 데이터 구조 후보

활동 하나는 여러 블록을 가진다.

```ts
type ActivityBlock = {
  id: string;
  type: string;
  title: string;
  description?: string;
  order: number;
  content: Record<string, unknown>;
};
```

예시:

```json
{
  "id": "block-01",
  "type": "canva_embed",
  "title": "도입 PPT",
  "order": 1,
  "content": {
    "embedUrl": "https://www.canva.com/design/.../view?embed",
    "height": 650
  }
}
```

미니활동 블록 예시:

```json
{
  "id": "block-03",
  "type": "interactive_activity",
  "title": "확률 시뮬레이터",
  "order": 3,
  "content": {
    "activitySlug": "probability-simulator",
    "reflectionType": "simple"
  }
}
```

## 11. 구현 순서 제안

지금 바로 전체 DB를 바꾸기보다, 코드 레벨에서 먼저 UI 구조를 실험한다.

추천 순서:

```text
1. 공통 ContentBlock 타입 정의
2. ActivityBlockNavigator 컴포넌트 만들기
3. 선택된 블록 하나만 중앙에 표시하는 구조 만들기
4. CanvaEmbed / YouTubeEmbed / GoogleDriveEmbed / ExternalEmbed 컴포넌트 만들기
5. interactive_activity 블록은 ProbabilitySimulator와 연결
6. 이후 실제 DB에 activity_content_blocks 테이블 또는 JSONB 구조 도입 검토
```

## 12. 현재 결론

새 MathLab의 UI는 기존의 긴 스크롤 방식에서 벗어나야 한다.

현재 추천 방향은 다음이다.

```text
단원 선택은 기존처럼 계층형으로 유지
소단원 내부는 콘텐츠 블록 목차 + 현재 블록 집중형 화면으로 전환
PPT/PDF/영상/미니활동은 블록 단위로 이동
PPT 상태 유지 문제는 숨김 처리, 고정 패널, 새 창 열기 중 상황에 맞게 해결
```

이 방향을 기준으로 다음 개발에서는 `ActivityRenderer`와 `ActivityBlockNavigator` 구조를 먼저 실험한다.
